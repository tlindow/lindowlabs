## 🚀 PR-Based Publishing Workflow (GitHub as a Feed)

Content publication in `content/` intentionally operates on a **Pull Request (PR) based workflow**:

1. **GitHub Activity as a Feed**: Publishing new essays, journal entries, or major updates via PRs broadcasts public activity across GitHub feeds, allowing followers and collaborators to see, read into, and engage with new writing in real time.
2. **Drafting to Shipping**:
   - Create a dedicated branch (e.g. `post/<slug>` or `journal/<topic>`).
   - Draft and refine the essay or journal markdown file in `content/`.
   - Open a PR with a descriptive title, overview, and key quotes for followers to engage with before merging into `main`.
3. **Canonical Markdown Record**: Merged posts remain as version-controlled markdown artifacts that can be consumed directly, syndicated to LinkedIn/blogs, or ingested by LLMs.
